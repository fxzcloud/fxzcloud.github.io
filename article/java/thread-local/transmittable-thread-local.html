                                                          # TransmittableThreadLocal

                                                          threadLocal解决了线程私有变量的问题； inheritableThreadLocal解决了父子线程之间变量传递的问题； transmittableThreadLocal在inheritableThreadLocal基础上解决了线程池复用情况下变量值传递的问题。

                                                          # 使用

                                                          使用比较简单，本质上需要注意两点：

                                                          • 对Runnable进行包装（使用TtlExecutor或者TtlRunnable都可），保证任务执行前后会执行抓取、重放、恢复操作。
                                                          • 需要保证抓取能抓到值，如何你使用的是TransmittableThreadLocal则不需要特殊处理，如果你用的是原生的ThreadLocal不要忘了把它注册一下。

                                                          详细的可以看单测逻辑：

                                                          # 原理

                                                          官方画的时序图：

                                                          ttl解决的问题是，怎么样才能在线程复用的情况下，子线程获取到提交任务线程中设置的值？

                                                          • 任务执行前，获取到线程threadLocal中的值。这一步称为：captured（捕获）。
                                                          • 任务执行中，把上一步主线程的值设置到当前线程的threadLocal中：replay（重放）。
                                                          • 任务执行后，把当前线程的值重新设置回当前线程：restore（恢复）。
                                                              public V call() throws Exception {
        // 捕获的主线程的值（这个值创建Callable的时候捕获的，此时已经在子线程中啦）
        final Object captured = capturedRef.get();
        if (captured == null || releaseTtlValueReferenceAfterCall && !capturedRef.compareAndSet(captured, null)) {
            throw new IllegalStateException("TTL value reference is released after call!");
        }
        // 重放到当前线程
        final Object backup = replay(captured);
        try {
            return callable.call();
        } finally {
            // 恢复
            restore(backup);
        }
    }

                                                          # captured

                                                          第一步captured我们可以在Runnable执行前，获取到主线程中的值：

                                                          public final class TtlCallable<V> implements Callable<V>, TtlWrapper<Callable<V>>, TtlEnhanced, TtlAttachments {
    // 主线程threadLocal值的引用
    private final AtomicReference<Object> capturedRef;
    private final Callable<V> callable;
    private final boolean releaseTtlValueReferenceAfterCall;

    private TtlCallable(@NonNull Callable<V> callable, boolean releaseTtlValueReferenceAfterCall) {
        // 这一步是执行捕获 获取主线程的值
        this.capturedRef = new AtomicReference<>(capture());
        this.callable = callable;
        this.releaseTtlValueReferenceAfterCall = releaseTtlValueReferenceAfterCall;
    }

                                                          holder变量可以看到收集了TransmittableThreadLocal。其中key是WeakHashMap，保证了TransmittableThreadLocal没有其他强引用的时候，变量可以被gc，避免了TransmittableThreadLocal引起的内存泄漏。

                                                          private static final InheritableThreadLocal<WeakHashMap<TransmittableThreadLocal<Object>, ?>> holder =
new InheritableThreadLocal<WeakHashMap<TransmittableThreadLocal<Object>, ?>>() {
    @Override
    protected WeakHashMap<TransmittableThreadLocal<Object>, ?> initialValue() {
        return new WeakHashMap<>();
    }

    @Override
    protected WeakHashMap<TransmittableThreadLocal<Object>, ?> childValue(WeakHashMap<TransmittableThreadLocal<Object>, ?> parentValue) {
        return new WeakHashMap<>(parentValue);
    }
};

                                                          但是holder是在哪里收集的呢？需要调用addThisToHolder方法。

                                                          private void addThisToHolder() {
    if (!holder.get().containsKey(this)) {
        holder.get().put((TransmittableThreadLocal<Object>) this, null); // WeakHashMap supports null value.
    }
}

                                                          TransmittableThreadLocal在set、get、remove分别会对ttl进行注册、移除注册操作，这样保证了我们可以收集到所有的ttl。

                                                          public final T get() {
    T value = super.get();
    if (disableIgnoreNullValueSemantics || value != null) addThisToHolder();
    return value;
}

/**
 * {@inheritDoc}
 */
@Override
public final void set(T value) {
if (!disableIgnoreNullValueSemantics && value == null) {
    // may set null to remove value
    remove();
} else {
    super.set(value);
    addThisToHolder();
}
}

/**
 * {@inheritDoc}
 */
@Override
public final void remove() {
    removeThisFromHolder();
    super.remove();
}

                                                          也就是ttl每次操作的时候都会对自己进行注册，我们可以在任务执行前通过holder变量获取到主线程的值拷贝啦。 但是这个前提是你要用ttl，实际开发中把threadLocal成本是很大的，并且有很多引用的第三方包的代码我们根本就没法修改，只能用threadLocal，那咋办呢？ 其实Transmitter中为我们提供了registerThreadLocal方法，我们可以把业务代码中用到的ThreadLocal注册进来，这样我们一样可以在任务执行前获取到threadLocal的值。 相关代码： 注册threadLocal：

                                                          public static <T> boolean registerThreadLocal(@NonNull ThreadLocal<T> threadLocal, @NonNull TtlCopier<T> copier, boolean force) {
    if (threadLocal instanceof TransmittableThreadLocal) {
        logger.warning("register a TransmittableThreadLocal instance, this is unnecessary!");
        return true;
    }

    synchronized (threadLocalHolderUpdateLock) {
        if (!force && threadLocalHolder.containsKey(threadLocal)) return false;

        WeakHashMap<ThreadLocal<Object>, TtlCopier<Object>> newHolder = new WeakHashMap<>(threadLocalHolder);
        newHolder.put((ThreadLocal<Object>) threadLocal, (TtlCopier<Object>) copier);
        threadLocalHolder = newHolder;
        return true;
    }
}

                                                          对threadLocal执行crr操作：

                                                           private static final Transmittee<HashMap<ThreadLocal<Object>, Object>, HashMap<ThreadLocal<Object>, Object>> threadLocalTransmittee =
                new Transmittee<HashMap<ThreadLocal<Object>, Object>, HashMap<ThreadLocal<Object>, Object>>() {
                    @NonNull
                    @Override
                    public HashMap<ThreadLocal<Object>, Object> capture() {
                        final HashMap<ThreadLocal<Object>, Object> threadLocal2Value = new HashMap<>(threadLocalHolder.size());
                        for (Map.Entry<ThreadLocal<Object>, TtlCopier<Object>> entry : threadLocalHolder.entrySet()) {
                            final ThreadLocal<Object> threadLocal = entry.getKey();
                            final TtlCopier<Object> copier = entry.getValue();

                            threadLocal2Value.put(threadLocal, copier.copy(threadLocal.get()));
                        }
                        return threadLocal2Value;
                    }

                    @NonNull
                    @Override
                    public HashMap<ThreadLocal<Object>, Object> replay(@NonNull HashMap<ThreadLocal<Object>, Object> captured) {
                        final HashMap<ThreadLocal<Object>, Object> backup = new HashMap<>(captured.size());

                        for (Map.Entry<ThreadLocal<Object>, Object> entry : captured.entrySet()) {
                            final ThreadLocal<Object> threadLocal = entry.getKey();
                            backup.put(threadLocal, threadLocal.get());

                            final Object value = entry.getValue();
                            if (value == threadLocalClearMark) threadLocal.remove();
                            else threadLocal.set(value);
                        }

                        return backup;
                    }

                    @NonNull
                    @Override
                    public HashMap<ThreadLocal<Object>, Object> clear() {
                        final HashMap<ThreadLocal<Object>, Object> threadLocal2Value = new HashMap<>(threadLocalHolder.size());

                        for (Map.Entry<ThreadLocal<Object>, TtlCopier<Object>> entry : threadLocalHolder.entrySet()) {
                            final ThreadLocal<Object> threadLocal = entry.getKey();
                            threadLocal2Value.put(threadLocal, threadLocalClearMark);
                        }

                        return replay(threadLocal2Value);
                    }

                    @Override
                    public void restore(@NonNull HashMap<ThreadLocal<Object>, Object> backup) {
                        for (Map.Entry<ThreadLocal<Object>, Object> entry : backup.entrySet()) {
                            final ThreadLocal<Object> threadLocal = entry.getKey();
                            threadLocal.set(entry.getValue());
                        }
                    }
                };

                                                          # replay

                                                          了解了Transmitter和ttl注册的逻辑，下面的代码就简单多了。

                                                          public static Object replay(@NonNull Object captured) {
    // 捕获的主线程的值
    final Snapshot capturedSnapshot = (Snapshot) captured;

    final HashMap<Transmittee<Object, Object>, Object> transmittee2Value = new HashMap<>(capturedSnapshot.transmittee2Value.size());
    for (Map.Entry<Transmittee<Object, Object>, Object> entry : capturedSnapshot.transmittee2Value.entrySet()) {
        Transmittee<Object, Object> transmittee = entry.getKey();
        try {
            // 根据第一步可以知道transmitteeCaptured其实是ttl以及ttl主线程的值引用所构成的HashMap
            Object transmitteeCaptured = entry.getValue();
            // 通过transmittee把捕获的值重放到当前线程，通过返回的是当前线程的值，后面用来恢复操作
            transmittee2Value.put(transmittee, transmittee.replay(transmitteeCaptured));
        } catch (Throwable t) {
            if (logger.isLoggable(Level.WARNING)) {
                logger.log(Level.WARNING, "exception when Transmitter.replay for transmittee " + transmittee +
                           "(class " + transmittee.getClass().getName() + "), just ignored; cause: " + t, t);
            }
        }
    }
    return new Snapshot(transmittee2Value);
}

                                                          public HashMap<TransmittableThreadLocal<Object>, Object> replay(@NonNull HashMap<TransmittableThreadLocal<Object>, Object> captured) {
    final HashMap<TransmittableThreadLocal<Object>, Object> backup = new HashMap<>(holder.get().size());

    // 我们知道holder是所有的ttl 这里get出来的值是当前线程的值
    for (final Iterator<TransmittableThreadLocal<Object>> iterator = holder.get().keySet().iterator(); iterator.hasNext(); ) {
        TransmittableThreadLocal<Object> threadLocal = iterator.next();

        // 保存tl和当前线程的值 用做恢复操作
        // backup
        backup.put(threadLocal, threadLocal.get());

        // clear the TTL values that is not in captured
        // avoid the extra TTL values after replay when run task
        if (!captured.containsKey(threadLocal)) {
            iterator.remove();
            threadLocal.superRemove();
        }
    }

    // 设置捕获的值到当前线程
    // set TTL values to captured
    setTtlValuesTo(captured);

    // 一个钩子函数 用来在ttl执行前后做一些操作
    // call beforeExecute callback
    doExecuteCallback(true);

    return backup;
}

                                                          这里就是把捕获主线程的值复制到当前线程，注意这里不是threadLocal.get()。

                                                          private static void setTtlValuesTo(@NonNull HashMap<TransmittableThreadLocal<Object>, Object> ttlValues) {
    for (Map.Entry<TransmittableThreadLocal<Object>, Object> entry : ttlValues.entrySet()) {
        TransmittableThreadLocal<Object> threadLocal = entry.getKey();
        threadLocal.set(entry.getValue());
    }
}

                                                          # restore

                                                          重放操作和上面就类似了：

                                                          public static void restore(@NonNull Object backup) {
    for (Map.Entry<Transmittee<Object, Object>, Object> entry : ((Snapshot) backup).transmittee2Value.entrySet()) {
        Transmittee<Object, Object> transmittee = entry.getKey();
        try {
            Object transmitteeBackup = entry.getValue();
            transmittee.restore(transmitteeBackup);
        } catch (Throwable t) {
            if (logger.isLoggable(Level.WARNING)) {
                logger.log(Level.WARNING, "exception when Transmitter.restore for transmittee " + transmittee +
                           "(class " + transmittee.getClass().getName() + "), just ignored; cause: " + t, t);
            }
        }
    }
}

                                                          @Override
public void restore(@NonNull HashMap<TransmittableThreadLocal<Object>, Object> backup) {
    // call afterExecute callback
    doExecuteCallback(false);

    for (final Iterator<TransmittableThreadLocal<Object>> iterator = holder.get().keySet().iterator(); iterator.hasNext(); ) {
        TransmittableThreadLocal<Object> threadLocal = iterator.next();

        // clear the TTL values that is not in backup
        // avoid the extra TTL values after restore
        if (!backup.containsKey(threadLocal)) {
            iterator.remove();
            threadLocal.superRemove();
        }
    }

    // restore TTL values
    setTtlValuesTo(backup);
}

                                                          private static void setTtlValuesTo(@NonNull HashMap<TransmittableThreadLocal<Object>, Object> ttlValues) {
    for (Map.Entry<TransmittableThreadLocal<Object>, Object> entry : ttlValues.entrySet()) {
        TransmittableThreadLocal<Object> threadLocal = entry.getKey();
        threadLocal.set(entry.getValue());
    }
}

                                                          一：在父子线程以及异步的情况下，如何保证在整个调用链路中传递spanId的传递？ 二：子线程递增了spanId，父线程如何感知？TransmittableThreadLocal中子线程的修改，是双向的吗？ 三：子线程递增了spanId，父线程感知不到，那么父线程执行多个子线程，如何保证spanId的递增传递？ 四：如果解决了多个子线程递增spanId的问题，那么子线程所有任务执行完后，需要清除叶子spanId，如何确认异步任务也执行完了？

                                                          # A

                                                          一：使用TransmittableThreadLocal来传递变量，保证父子线程以及线程池线程复用的情况下，子线程中可以感知到spanId值。

                                                          二：使用TransmittableThreadLocal，子线程中对于变量的值修改，父线程是否可以感知到，这个其实要分情况：

                                                          • 使用 TransmittableThreadLocal 时，对于不可变类型（如 String、Integer），子线程对这些变量的修改不会影响父线程中的值，因为这些类型是不可变的，每次修改都会产生新的对象实例。
                                                          • 对于可变类型的自定义对象，子线程对这些对象的修改会影响父线程中的值，因为所有线程操作的是相同的对象实例的引用。

                                                          所以其实我们有两种方法，

                                                          • 一种是用引用类型，这样可以保证父子线程之间的修改均可以感受到，比如AtomicInteger。

                                                          • 一种是用不可变类型，这样父子线程之间的修改不会相互影响，我们可以用全局的HashMap来存，这样相当于在父子线程之间透传了这个引用。

                                                          三：用全局的HashMap来存，这样相当于在父子线程之间透传了这个引用。 四：这里又分两种情况，

                                                          • 第一种是采用非引用类型的情况。这个全局的map里的信息要在所有任务执行完清掉，主要是异步任务，我们可以采用引用计数法，重写线程池的beforeExecute和afterExecute方法，来标识异步任务也执行完了
                                                          • 第二种是采用了引用类型的情况。这种情况下不需要全局的map了，理论上用TransmittableThreadLocal就可以双向透传，问题是啥时候清掉TransmittableThreadLocal里的值呢？
                                                            • 当线程执行完毕时，它所对应的 TransmittableThreadLocal 里的值会被清除。这是为了避免内存泄漏，确保线程局部变量不会在线程退出后继续占用内存。TransmittableThreadLocal 的这种设计保证了线程局部变量的生命周期与线程的生命周期一致，避免了不必要的内存占用。也就是说，我们只需要主线程中remove一下保证主线程没有对这个引用的持有，子线程执行完也会清掉这个引用，这个引用是不是就没任何地方持有了～ gc会回收掉。

                                                          # 一：引用计数法

                                                          /*
 * DistributedTracer(DT) use demo.
 *
 * @author Jerry Lee (oldratlee at gmail dot com) <br/>
 * <p>
 * 执行日志：
 * <p>
 * // 调用前增加引用计数 表示此次rpc调用开始 引用计数为1<br/>
 * DEBUG: Increase reference counter(1) for traceId traceId_XXXYYY in thread main
 * <p>
 * // rpc调用server 1 此时获取map中的spanId当前值递增 此时spanId为：1.1.1<br/>
 * Do Rpc invocation to server server 1 with {traceId=traceId_XXXYYY, spanId=1.1.1}
 * <p>
 * // rpc调用server 3 此时获取map中的spanId当前值递增 此时spanId为：1.1.2<br/>
 * Do Rpc invocation to server server 3 with {traceId=traceId_XXXYYY, spanId=1.1.2}
 * <p>
 * // rpc异步调用server 2之前 递增引用计数 表示我异步任务还没执行完 你别动 引用计数为2<br/>
 * DEBUG: Increase reference counter(2) for traceId traceId_XXXYYY in thread Executors
 * <p>
 * // 主线程执行完了 递减引用计数 表示我不管你 反正老子主线程执行完了 把计数减一 要是计数成了0 就把本次spanId信息在map中清掉 但是这里计数为1 表示还有异步任务还没执行完 所以spanId信息还不能清掉<br/>
 * DEBUG: Decrease reference counter(1) for traceId traceId_XXXYYY in thread main
 * <p>
 * // rpc异步调用server 2 此时获取map中的spanId当前值递增 此时spanId为：1.1.3<br/>
 * Do Rpc invocation to server server 2 with {traceId=traceId_XXXYYY, spanId=1.1.3}
 * <p>
 * // rpc调用server 2之后 递减引用计数 表示我异步任务执行完了 你可以根据引用计数看一下是不是都执行完了 这里计数为0 表示所有异步任务都执行完了 可以清掉spanId信息了<br/>
 * DEBUG: Decrease reference counter(0) for traceId traceId_XXXYYY in thread Executors
 * <p>
 * // 引用计数都没了 清掉map中的spanId信息 表示这次rpc调用结束<br/>
 * DEBUG: Clear traceId2LeafSpanIdInfo for traceId traceId_XXXYYY in thread Executors
 */
public class DistributedTracerRefCountDemo {

    /**
     * 线程基础信息<br/>
     * 持有traceId和baseSpanId<br/>
     * 重写了beforeExecute和afterExecute方法，用于增加和减少spanId的引用计数
     */
    private static final TransmittableThreadLocal<DtTransferInfo> transferInfo = new TransmittableThreadLocal<DtTransferInfo>() {
        protected void beforeExecute() {
            super.beforeExecute();

            /**
             * 在线程执行前增加spanId的引用计数<br/>
             * 表示当前异步的任务还没执行完，你别清空traceId2LeafSpanIdInfo中的信息
             */
            increaseSpanIdRefCount();
        }

        protected void afterExecute() {
            /**
             * 在线程执行后减少spanId的引用计数<br/>
             * 表示当前异步的任务已经执行完，你可以根据引用判断是否清空traceId2LeafSpanIdInfo中的信息
             */
            decreaseSpanIdRefCount();
        }
    };

    /**
     * traceId到LeafSpanIdInfo的映射<br/>
     * 持有叶子span的当前值和引用计数
     */
    private static final ConcurrentHashMap<String, LeafSpanIdInfo> traceId2LeafSpanIdInfo = new ConcurrentHashMap<>();

    /**
     * ttl包装的线程池
     */
    private static final java.util.concurrent.ExecutorService executorService = TtlExecutors.getTtlExecutorService(Executors.newFixedThreadPool(1, r -> {
        Thread thread = new Thread(r, "Executors");
        thread.setDaemon(true);
        return thread;
    }));

    public static void main(String[] args) throws InterruptedException {
        // 执行rpc调用
        rpcInvokeIn();

        Thread.sleep(1000);
    }

    /**
     * DistributedTracer Framework Code
     */
    private static void rpcInvokeIn() {
        // Get Trace Id and Span Id from RPC Context
        String traceId = "traceId_XXXYYY";
        String baseSpanId = "1.1";

        // Set Trace Id and Span Id to ThreadLocal
        transferInfo.set(new DtTransferInfo(traceId, baseSpanId));

        // Set Trace Id to traceId2LeafSpanIdInfo
        traceId2LeafSpanIdInfo.put(traceId, new LeafSpanIdInfo());

        // Increase reference counter for spanId
        increaseSpanIdRefCount();

        // Biz Code
        syncMethod();

        // Decrease reference counter for spanId
        decreaseSpanIdRefCount();
    }

    private static void syncMethod() {
        // async call by TTL Executor
        Objects.requireNonNull(executorService).submit(DistributedTracerRefCountDemo::asyncMethod);

        // async call by new Thread
        // FIXME Bug!! 没有 Increase/Decrease reference counter操作!
        new Thread(DistributedTracerRefCountDemo::syncMethodByNewThread, "Thread-by-new").start();

        invokeServerWithRpc("server 1");
    }

    private static void asyncMethod() {
        invokeServerWithRpc("server 2");
    }

    private static void syncMethodByNewThread() {
        invokeServerWithRpc("server 3");
    }

    // RPC invoke
    private static void invokeServerWithRpc(String server) {
        // Increase leaf span current
        int leafSpanCurrent = increaseLeafSpanCurrentAndReturn();

        // Set RpcContext
        // Mocked, should use RPC util to get Rpc Context instead
        Map<String, String> rpcContext = new ConcurrentHashMap<>();
        DtTransferInfo info = transferInfo.get();
        rpcContext.put("traceId", info.getTraceId());
        rpcContext.put("spanId", info.getBaseSpanId() + "." + leafSpanCurrent);

        // Do Rpc
        System.out.printf("Do Rpc invocation to server %s with %s%n", server, rpcContext);
    }

    /**
     * 增加spanId的引用计数
     */
    private static void increaseSpanIdRefCount() {
        DtTransferInfo info = transferInfo.get();
        String traceId = info.getTraceId();
        LeafSpanIdInfo leafSpanIdInfo = traceId2LeafSpanIdInfo.get(traceId);
        int refCounter = leafSpanIdInfo.getRefCounter().incrementAndGet();

        System.out.printf("DEBUG: Increase reference counter(%s) for traceId %s in thread %s%n", refCounter, traceId, Thread.currentThread().getName());
    }

    /**
     * 减少spanId的引用计数<br/>
     * 如果引用计数为0则清除traceId2LeafSpanIdInfo中的映射
     */
    private static void decreaseSpanIdRefCount() {
        DtTransferInfo info = transferInfo.get();
        String traceId = info.getTraceId();
        LeafSpanIdInfo leafSpanIdInfo = traceId2LeafSpanIdInfo.get(traceId);

        int refCounter = leafSpanIdInfo.getRefCounter().decrementAndGet();
        System.out.printf("DEBUG: Decrease reference counter(%s) for traceId %s in thread %s%n", refCounter, traceId, Thread.currentThread().getName());

        if (refCounter == 0) {
            traceId2LeafSpanIdInfo.remove(traceId);
            System.out.printf("DEBUG: Clear traceId2LeafSpanIdInfo for traceId %s in thread %s%n", traceId, Thread.currentThread().getName());
        } else if (refCounter < 0) {
            throw new IllegalStateException("Leaf Span Id Info Reference counter has Bug!!");
        }
    }

    /**
     * 递增叶子span的当前值
     *
     * @return 递增后的span值
     */
    private static int increaseLeafSpanCurrentAndReturn() {
        DtTransferInfo info = transferInfo.get();
        String traceId = info.getTraceId();
        return traceId2LeafSpanIdInfo.get(traceId).getCurrent().getAndIncrement();
    }

    /**
     * ttl持有的线程基础信息<br/>
     * 因为baseSpanId和traceId是不变得 所以不需要考虑父子线程之间变量修改后同步的问题
     */
    private static class DtTransferInfo {
        private final String traceId;
        private final String baseSpanId;

        public DtTransferInfo(String traceId, String baseSpanId) {
            this.traceId = traceId;
            this.baseSpanId = baseSpanId;
        }

        public String getTraceId() {
            return traceId;
        }

        public String getBaseSpanId() {
            return baseSpanId;
        }
    }

    /**
     * 叶子span的信息<br/>
     * 由于子线程会修改current，并且父线程和其他子线程需要感知到变化，所以需要将LeafSpanIdInfo放到ConcurrentHashMap中<br/>
     * 由于一次rpc调用完成，需要清除traceId2LeafSpanIdInfo，所以需要增加引用计数，当计数为0则意味着需要清掉ConcurrentHashMap中的映射<br/>
     */
    private static class LeafSpanIdInfo {

        /**
         * 当前span值<br/>
         * 用于子线程之间计数
         */
        private final AtomicInteger current = new AtomicInteger(1);

        /**
         * span引用计数<br/>
         * 当引用计数为0时，清除traceId2LeafSpanIdInfo中的映射，表示此链路此次调用结束
         */
        private final AtomicInteger refCounter = new AtomicInteger(0);

        public AtomicInteger getCurrent() {
            return current;
        }

        public AtomicInteger getRefCounter() {
            return refCounter;
        }
    }
}

                                                          /**

public class DistributedTracerDemo {
    private static final ExecutorService executorService;

    static {
        ExecutorService service = Executors.newFixedThreadPool(1, r -> {
            Thread t = new Thread(r, "Executors");
            t.setDaemon(true);
            return t;
        });

        executorService = TtlExecutors.getTtlExecutorService(service);
    }

    public static void main(String[] args) {
        rpcInvokeIn();

        System.out.println("WARN: finished rpc invocation");

        // Help to check GC status
        try {
            Thread.sleep(200);
        } catch (InterruptedException e) {
            Thread.currentThread().interrupt();
        }
        System.out.println("WARN: Call System.gc");
        System.gc();
        System.out.println("WARN: Called System.gc");
        try {
            Thread.sleep(100);
        } catch (InterruptedException e) {
            Thread.currentThread().interrupt();
        }

        System.out.println("Exit Main.");
    }

    private static void rpcInvokeIn() {
        ////////////////////////////////////////////////
        // DistributedTracer Framework Code
        ////////////////////////////////////////////////

        // Get Trace Id and Span Id from RPC Context
        String traceId = "traceId_XXXYYY" + traceIdCounter.getAndIncrement();
        String baseSpanId = "1.1";

        LeafSpanIdInfo leafSpanIdInfo = new LeafSpanIdInfo();
        transferInfo.set(new DtTransferInfo(traceId, baseSpanId, leafSpanIdInfo));

        ////////////////////////////////////////////////
        // Biz Code
        ////////////////////////////////////////////////
        syncMethod();

        ////////////////////////////////////////////////
        // DistributedTracer Framework Code
        ////////////////////////////////////////////////
        System.out.printf("Finished Rpc call %s with span %s.%n", traceId, leafSpanIdInfo);

        // Release context in ThreadLocal, avoid to be held by thread, GC friendly.
        transferInfo.remove();
    }

    private static void syncMethod() {
        // Async call by TTL Executor
        executorService.submit(DistributedTracerDemo::asyncMethod);

        // Async call by new Thread
        new Thread(DistributedTracerDemo::syncMethod_ByNewThread, "Thread-by-new").start();

        invokeServerWithRpc("server 1");
    }

    private static void asyncMethod() {
        try {
            Thread.sleep(3);
        } catch (InterruptedException e) {
            Thread.currentThread().interrupt();
        }
        invokeServerWithRpc("server 2");
    }

    private static void syncMethod_ByNewThread() {
        try {
            Thread.sleep(2);
        } catch (InterruptedException e) {
            Thread.currentThread().interrupt();
        }
        invokeServerWithRpc("server 3");
    }

    // RPC invoke
    private static void invokeServerWithRpc(String server) {
        ////////////////////////////////////////////////
        // DistributedTracer Framework Code
        ////////////////////////////////////////////////

        int leafSpanCurrent = increaseLeafSpanCurrentAndReturn();

        // Set RpcContext
        // Mocked, should use RPC util to get Rpc Context instead
        ConcurrentHashMap<String, String> rpcContext = new ConcurrentHashMap<>();

        DtTransferInfo info = transferInfo.get();
        if (info != null) {
            rpcContext.put("traceId", info.traceId);
            rpcContext.put("spanId", info.baseSpanId + "." + leafSpanCurrent);
        }

        // Do Rpc
        // ...
        System.out.printf("Do Rpc invocation to server %s with %s%n", server, rpcContext);
    }

    ///////////////////////////////////////////////////////////////////////
    // Span id management
    ///////////////////////////////////////////////////////////////////////

    private static final AtomicLong traceIdCounter = new AtomicLong();

    static class LeafSpanIdInfo {
        final AtomicInteger current = new AtomicInteger(1);

        @Override
        public String toString() {
            return "LeafSpanIdInfo{current=" + current + '}';
        }
    }

    static class DtTransferInfo {
        final String traceId;
        final String baseSpanId;
        final LeafSpanIdInfo leafSpanIdInfo;

        DtTransferInfo(String traceId, String baseSpanId, LeafSpanIdInfo leafSpanIdInfo) {
            this.traceId = traceId;
            this.baseSpanId = baseSpanId;
            this.leafSpanIdInfo = leafSpanIdInfo;
        }

        @Override
        protected void finalize() throws Throwable {
            super.finalize();
            System.out.printf("DEBUG: gc DtTransferInfo traceId %s in thread %s: %s%n",
                    traceId, Thread.currentThread().getName(), this);
        }
    }

    private static final TransmittableThreadLocal<DtTransferInfo> transferInfo = new TransmittableThreadLocal<>();

    private static int increaseLeafSpanCurrentAndReturn() {
        DtTransferInfo info = transferInfo.get();
        return (info != null) ? info.leafSpanIdInfo.current.getAndIncrement() : 0;
    }

    }

                                                          # 测试

                                                          测试子线程的修改父线程是否可以感知。

                                                          • 一种是用引用类型，这样可以保证父子线程之间的修改均可以感受到，比如AtomicInteger。
                                                          • 一种是用不可变类型，这样父子线程之间的修改不会相互影响，我们可以用全局的HashMap来存，这样相当于在父子线程之间透传了这个引用。
                                                          /**
 * 测试子线程的修改父线程是否可以感知
 * 
 * @author fxz
 */
public class DistributedTracerTestDemo {

    static ExecutorService service = Executors.newFixedThreadPool(1);

    static ExecutorService executorService = TtlExecutors.getTtlExecutorService(service);

    public static void main(String[] args) {
        testString();
        testAtomInteger();
    }

    public static void testString() {
        final TransmittableThreadLocal<String> parent = new TransmittableThreadLocal<String>();
        parent.set("父线程设置的");

        executorService.submit(() -> {
            System.out.println("子线程能获取到父线程设置的值吗》" + parent.get());
            parent.set("子线程设置的");
        });

        try {
            Thread.sleep(100);
        } catch (InterruptedException e) {
            throw new RuntimeException(e);
        }

        String value = parent.get();
        System.out.println("父线程能获取到子线程设置的值吗》" + value);
    }

    public static void testAtomInteger() {
        AtomicInteger atomicInteger = new AtomicInteger(99);
        final TransmittableThreadLocal<AtomicInteger> parent = new TransmittableThreadLocal<AtomicInteger>();
        parent.set(atomicInteger);
        System.out.println("父线程设置的值》" + parent.get().get());

        executorService.submit(() -> {
            AtomicInteger atomic = parent.get();
            System.out.println("子线程能获取到父线程设置的值吗》" + atomic.get());

            atomic.addAndGet(1);
            parent.set(atomic);
            System.out.println("子线程设置的值》" + parent.get().get());
        }
                              );

        try {
            Thread.sleep(100);
        } catch (InterruptedException e) {
            throw new RuntimeException(e);
        }

        System.out.println("父线程能获取到子线程设置的值吗》" + parent.get().get());
    }

}
